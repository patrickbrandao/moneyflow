# 001 — Stack e entrega

| Tema | Decisão |
|---|---|
| Frontend | Template da skill `purple-skills-public:web-interface-admin-with-canva`: React 19, Vite, TypeScript, Tailwind 4, React Flow, cmdk, lucide. Seguir as regras de design da skill (tokens, sem hex em componentes, um único acento, sem sombra em superfície fixa). O acento é azul nos dois temas (o roxo do template foi trocado em 2026-10-11, tarefa 007); nenhuma cor da interface, do logo ou da paleta de categorias `--port-1`…`--port-12` fica na faixa roxa (matiz 250°–320°). Todo token usado como texto (`--text`, `--text-dim`, `--text-muted`, `--text-faint`, os estados `--ok`/`--warn`/`--danger`/`--info`, `--negative` e `--accent-soft`) passa AA (4,5:1) sobre o fundo, o cartão e o campo nos dois temas (tarefa 175; conferido em `e2e/tests/tema.spec.ts`). |
| Backend | Node + TypeScript, Fastify, Drizzle ORM (só consultas; schema gerado do banco), Zod. |
| Banco | PostgreSQL 18 + pgvector, em `database/`, gerido pelo agente DBA ([016](016-banco-de-dados.md)). Migrations SQL com dbmate, testes pgTAP. Anexos também no Postgres (`bytea`, tabela própria, limite por arquivo). |
| Repositório | Monorepo pnpm em `github.com/patrickbrandao/moneyflow`: `apps/web`, `apps/server` (modos `api` e `worker`), `packages/shared` (schemas Zod, tipos, definições das tools dos agentes), `packages/db` (schema Drizzle gerado do banco). O banco fica em `database/`, fora dos workspaces. |
| Qualidade | Biome (lint/format), pgTAP no banco, Vitest + Testcontainers (Postgres 18 real) para regras financeiras, Playwright nos fluxos principais. Dois níveis de verificação: rápida no desenvolvimento (`pnpm verify:quick`, só o que mudou, integração no Postgres local) e completa sob pedido, antes de PR e release e sempre no CI (`pnpm verify:full`). |
| Imagem | Imagem única `tmsoftbrasil/moneyflow`: a API serve o SPA compilado; o mesmo artefato roda como `api` ou `worker`. |
| Cabeçalhos de segurança | Toda resposta da API leva `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff` e `Referrer-Policy: same-origin` (hook `onSend` em `apps/server/src/security-headers.ts`). O HTML do SPA leva a CSP `default-src 'self'`, `script-src 'self'` mais o hash sha256 de cada `<script>` inline do `index.html` (o do tema; calculado no boot a partir do `index.html` compilado, então mudar o script não exige mexer na CSP), `style-src 'self' 'unsafe-inline' https://fonts.googleapis.com` (atributos `style` do React; o markdown saneado não tem `style`, tarefa 073), `font-src 'self' https://fonts.gstatic.com data:`, `img-src`/`media-src 'self' data: blob:` (prévias, gravação, exportações; imagens externas no markdown não carregam), `worker-src 'self' blob:` (worker do pdf.js), `connect-src 'self'`, `object-src 'none'`, `base-uri 'self'`, `form-action 'self'` e `frame-ancestors 'none'`. Sem `unsafe-eval`: o console desliga o JIT do Zod (`@moneyflow/shared/zod-jitless`, primeiro import do `main.tsx`). Uma resposta que já define a própria CSP (o `sandbox` dos downloads de anexo) fica com ela; sem SPA servido, um HTML sai só com `frame-ancestors 'none'; object-src 'none'; base-uri 'self'`. |
| Ambiente local | Docker Compose: o compose da raiz inclui `database/docker-compose.yml` (Postgres 18 + pgvector), aplica as migrations num one-shot (dbmate) e sobe `api` e `worker`. O Postgres dessa pilha tem volume próprio e sai na porta 5433, só em loopback (`STACK_DB_BIND`, padrão `127.0.0.1`; `0.0.0.0` o expõe na rede de propósito), para conviver com o banco de desenvolvimento de `database/` (5432), usado por `pnpm dev`. Segredos locais de integrações (a chave do CNPJ Aberto, spec 003) ficam em `.local/` (fora do git e da imagem), carregados pelo compose e pelo `pnpm dev`. A API publica a porta direto, sem proxy: `TRUSTED_PROXIES` fica vazio (o IP do cliente é o da conexão, [002](002-usuarios-e-permissoes.md)); atrás de um proxy reverso, liste-o nessa variável. |
| CI/CD | GitHub Actions: lint, typecheck, testes e build em PRs/main. Em tag `v*`: build multi-arch (amd64+arm64) e push `:X.Y.Z` e `:latest` (secrets `DOCKERHUB_USERNAME` e `DOCKERHUB_TOKEN`). `make release` para push local (conta `tmsoftbrasil` autorizada na máquina). |
| Locale | Interface pt-BR com strings centralizadas (i18n-ready), fuso `America/Sao_Paulo`, `dd/mm/aaaa`, `R$ 1.234,56`. Código e banco em inglês. |
| Moeda | Só BRL, valores em centavos (`bigint`). |
